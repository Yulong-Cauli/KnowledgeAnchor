# 补充测试集，统计 nuScenes 全部场景

2026-11-08，用户要求补上测试集。本轮覆盖训练、验证、测试共1000段驾驶记录，分别报告三个集合，并合并给出整体比例。此前850场景的设计和报告另存为 `../README-trainval-v1.md`、`../RESULTS-trainval-v1.md`，原结果文件不覆盖。

## 沿用的定义

观察车辆随后约3秒的运动。每段记录末尾没有完整后续六个采样点的时刻不计入统计。从当前位置沿车头朝向画一条直线，约3秒后的位置到这条直线的距离小于2米，就计为“横向位移小”。仍按未来六个keyframe定义窗口，实际时长单独记录。

同样报告停止（整个窗口路径长≤0.3m）、低速（0.3–1.5m）和移动（>1.5m）分组，以及整个窗口内最大横向偏移、累计朝向变化、逐场景分布。所有阈值与上次相同，不根据测试集数字调整。

主命题仍为整体比例严格>50%；不要求接近论文或此前结果。若测试集反例、任何分组不同或数据完整性失败，原样报告，不删样本来维持结论。

## 执行方式与来源

- 训练/验证部分复用前次已核验的逐样本结果，不重新训练或改变计算方法。Kaggle 将旧 notebook 的输出挂载为只读输入；加载前核对原始CSV SHA256、原JSON和原官方比对结果，再复算全部15个旧总体。
- 测试集直接从官方 `https://motional-nuscenes.s3.amazonaws.com/public/v1.0/v1.0-test_meta.tgz` 读取，不需要Kaggle镜像、不读取隐藏评测标注。仅保存 scene/sample/sample_data/ego_pose 四表到临时目录，记录内容SHA256和HTTP来源信息，原数据不入Git。
- 官方场景划分沿用固定devkit commit `b40adc467b919192899405d9b77871afee8efa07`，增加同一源文件中的150个test场景，见 `sources/splits-all.json`。三集合场景集合必须无重叠且共1000个。
- 测试集应有150场景、6008采样时刻；检查每段链长度、prev/next、样本归属、LIDAR与位姿一一对应、时间戳和单位四元数。完整未来六步样本数量从链实际计数，不仅套减法。
- 计算直接调用前次未改动的 `census.py` 中 `motion_metrics`，记录其源码SHA256。新代码只增加测试集数据读取与合并统计。
- Kaggle CPU运行，无GPU、无模型训练。新kernel：`cauliyulong/claim-nuscenes-all-census`，旧kernel保持version 1，不覆盖其证据。

## 合并与检查

报告 `all`、`trainval`、`train`、`val`、`test` 五种范围×五种运动分组，共25个总体；敏感性表5×5×14=350行。合并前检查样本token与场景集合互斥；用整数分子、分母相加，不平均三个百分比。全量逐样本表以无损gzip归档，单文件<5MB；输出日志、输入/源码/设计哈希、环境和确切Kaggle版本号。

这仍是同一描述性普查的范围扩展。没有用测试集调模型，但也不把它包装成事先设计的独立验证；不涉及捷径因果。卡片保持asserted / watch，signoff不由Agent填写。
