# style-guide — 卡面文字整改标准（P0 产出，2026-11-10 01:0x）

> 依据主人 2026-11-10 批示与其签署定稿的两张 verified 卡（样板）提炼。所有判例来自库内真卡。
> 铁律不受本指南影响：evidence 行（source/locator/quote/relation）、id/status/stance/review_due/signoff、核查记录节、历史标记块一律不动。

## 主人样板的特征（正面标准）

1. **主张概述=结论+关键数字+分母**：开门第一句就是"本库对 X 复算，统计到 708 对…占 0.0823%，低于 0.1%"。没有"本卡旨在/这条主张是什么意思"的元话语。
2. **实验定义写到能复算**：中心公式 `(x + w/2, y + h/2)`、分组口径、取整方式、`n(n−1)/2` 计法、分位数定义全部一句一句写清。
3. **表格带原始计数与分母**：不只给百分比，给 `29783 / 34157 / 87.19%`。
4. **偏差直说**：比论文多 94 对（15.3%）就写多 94 对，并说明落在预设带内。
5. **一句话闭环**：主张→证据→可推翻条件→机制含义→剩余缺口（"模型实际漏检率需要用检测输出评估，仍待单独统计"），一句收束，不层层展开。
6. **归属声明只出现该出现的地方**：论文声称/本库实测/复算/推导——各说一次，说清即可。

## 四类病灶判例（原句 → 为什么病 → 怎么改）

### ① 意义不明

- **判例 1**（bevplanner-egomlp-parity）："另关联 nuScenes 数据集性质卡，但数据分布普查不以本卡的模型持平现象为前提，两者不能互相替代验证。"——双重否定绕弯，读三遍才知道在说什么。→ 改："nuScenes 数据分布普查卡与本卡互不替代：本卡证『模型持平』现象，普查证『数据分布』背景。"
- **判例 2**（同卡正文混班次账目）："2026-11-08 原 imbalance 卡已由 nuScenes 数据集性质卡替代，旧『四卡归因依存』不再适用于该新卡。"——版本管理语言进了正文。→ 班次账目移核查记录（已有核查记录的不重复搬），正文只写当前事实。
- **判例 3**（brecq 卡）："必须记住的三个限定："——命令式元话语，信息量为零。→ 直接"三个限定："。
- **节名病**："我的理解"/"这条主张是什么意思" → "主张"；"证据支持到哪里" → "证据与边界"；"可能的解释与未排除的因素" → "解释与未排除因素"；"适用范围与迁移限制" → "范围与迁移限制"；"对研究问题的启发" → "研究启发"；"当前立场与下一步" → "下一步"；"若成立 / 不成立意味着什么" → "成立/不成立的含义"。

### ② 过度防御

- **判例 1**（brecq 卡 title，90 字三层括号套三层）："BRECQ 自报：W4A4 下用 1024 张校准图、0.4–0.8 GPU hours 达到与 QAT 可比精度（ResNet-18 69.60 vs PACT 69.2；MobileNetV2 66.57 超两者），仍低于 QAT 最强 LSQ 71.1"——title 该是一句能读的主张。→ 改："BRECQ 自报：W4A4 用 1024 张校准图与 QAT 精度可比（R18 69.60 / MobileNetV2 66.57），低于 LSQ 71.1"——口径细节在 scope/正文有，title 不必全背。
- **判例 2**（njusparseocc-rayiou34 卡，同一事实三处重复）："RayIoU 系本文提出指标"在 scope、falsifier 2 的括号注、正文限定 1 各完整陈述一遍。→ 保留一处完整陈述（falsifier 注），其余一句话引用"（见 falsifier 2 注）"。
- **判例 3**（同卡顶部修订注记 blockquote）："> 修订注记（2026-11-03 基线行修正）：笔记 §3 …本卡 title、scope、evidence…已同步；falsifier 1 阈值（33.7→33.5）…"——修订史全文占正文开头。→ 压缩成一句指针进核查记录或保留一行"基线行已按 v5 修正（见核查记录 2026-11-03）"，正文直接给当前事实。
- **红线提醒**：以下不是防御性废话，**不许删**——「论文声称/作者报告/本库实测/复算/推导」归属声明；真实证据缺口（如"基线是否作者复训论文未写明"）；历史标记卡的全部标记。

### ③ 自我窄化

- **判例 1**（brecq 卡 scope 堆四件事）：scope 里塞了数据集/模型/位元 + 校准成本口径 + 对比行转引声明 + 摘要声称辨析，一句到底。→ scope 回到"数据集/模型/条件"三要素（对齐样板卡 scope 的密度），转引声明与摘要辨析移正文或 falsifier。
- **判例 2**（egomlp 卡分类学自述）："这是 bevplanner 机制系的『现象』卡，关联注入位置、速度扰动与指标后果等检查。"——库内分类学没有信息量。→ 删或并入 related 一句话。
- **反向故障（同样扣分）**：把"论文声称 X"改成"论文似乎暗示可能 X"= 归属降级失真；把 scope 削到与 evidence 不匹配 = 窄化。改写必须保持主张强度与证据强度一致。

### ④ 不闭环

- **判例 1（正面）**：egomlp 卡"下一步"节是好样板——固定什么（数据 split、指标实现、0.1m 网格）/只改什么（有无感知输入）/观察什么（L2-Avg/Colli-Avg 差距）/结果怎么改变判断（落后 2 倍→按 falsifier 登记；持平→现象成立但仅行为复现）。批量改写时把空洞下一步都改成这个结构。
- **判例 2**（brecq 卡待验证）："澄清 240× 的分母（相对什么流程的 production 时间）"——这条其实闭环（有明确检查对象）；但"复现一下"式的必须展开成固定/改变/观察/判据。
- **判例 3**：falsifier 若写成"数据或代码有错就重算"类通用要求（AGENTS.md 明令不凑可推翻条件）→ 改写成具体的可推翻预测；若 falsifier 描述的现象与 title 主张对不上 → 以 evidence 能支撑的主张为准改写 falsifier，不许造新事实。

## 改写作业流程（每张卡）

1. 读全卡 → 对照样板自问三问：第一句能不能直接给结论？定义能不能复算？读完知不知道"下一步做什么、什么结果算推翻"？
2. 只改 prose（title/scope/falsifiers/正文节）；数字、quote、id、status、stance、related、核查记录不动。
3. 自查：改后主张=改前主张；证据仍支撑；falsifier 仍能推翻；归属声明仍在；历史标记未动。
4. 三计数记账：改动 / 原样保留（KEEP）/ 登记（QUESTIONS-prose）。
