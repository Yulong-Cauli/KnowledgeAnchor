# KnowledgeAnchor：六张 claim 的夜间复核提示词

这是可复制的任务提示词草案；尚未启动任务，也不是已批准的训练方案。

## 分派方式

给下游 Agent 发送「共同前缀」及对应的一个任务后缀。四份作业覆盖六张卡：

| 作业 | 覆盖卡 | 共享关系 | 本轮重点 |
| --- | --- | --- | --- |
| A：BEVDet | Scale-NMS；Tiny vs FCOS3D | 共用 Tiny 权重、干净预测、评测环境 | 先完成 NMS 配对，再扩展精度与计算量 |
| B：VAD | ego status 注入；ego velocity 扰动 | 共用 VAD-Base、数据、规划评测 | 官方基线与 Table 2 优先；Table 1 取决于匹配权重 |
| C：Ego-MLP | Ego-MLP 持平 | 读取 B / D 的独立复算参照行 | 防泄露审计；已有权重评测，或先提交训练方案 |
| D：UniAD | 后处理提高 CCR | 与 B / C 对齐指标协议 | P.P. 配对复算与 CCR 实现审查 |

四位 Agent 的准备工作可并行，GPU 工作按实际配额排队。「一个 GPU 会话」是资源预算，不是保证一夜跑完。默认每项作业最多一个 GPU 会话，不自行增加付费资源。

建议优先取得 A 的 NMS 配对、B 的 clean / Blank / 速度扰动；FCOS3D 扩展和 D 的全量运行随后按资源排队。C 先并行审计，取得匹配权重或完整训练方案获批后再入计算队列。

以下参考数字均来自当前卡片或库内笔记，仍为论文声称、尚未独立验证；不是新获取的官方权重或实测结果。执行者须重新核对当前上游代码、权重、数据可得性。

### 2. 先审计，再计算

在 README 建立「论文行 → 代码入口 → 配置 → 权重 → 数据 → 指标」映射：

- 固定官方来源、上游 commit、配置及 hash，改动保存为可追溯补丁并计 hash。
- checkpoint 记录来源、大小、SHA256、对应模型、输入尺寸和训练配方，不拿同名新版本替换论文模型。
- 检查加载的 missing / unexpected keys，解释每项差异；不忽略不匹配却仍称原配置复现。
- 数据检查访问权限、实际文件、版本、split、样本数、token 清单 hash、标注与地图版本。能列目录不代表能挂载并运行，必须真实读取并最小执行。
- 缺失资料如实标缺失，不编造来源、引文或版本 URL。需要登录、接受条款或授权时记录具体动作，继续不依赖该动作的工作。

首个目标评测前保存带时间戳和 hash 的预注册设计：比较矩阵、样本范围、指标、种子、配置、判断口径、预算。运行后不得回调阈值、挑有利样本。新增探索另立版本并标为事后分析。

卡内明确预设的数值判据原样保留，核对其前提和适用范围。对没有严格定义的「显著」「明显」「持平」，先报告原始指标与差值，不自行补一个阈值便宣布成立或失败。需要新增判断标准时提出建议留用户裁定，不阻止无阈值的事实测量。

### 3. 执行、资源与预算

先读 STATE 恢复状态；已有远端运行先查状态，禁止重复提交。依次完成：环境 / 数据 / 权重预检 → 完整单场景或小样本试跑 → 干净基线 → 主要配对实验 → 余量扩展 → 收回结果。

默认单作业总墙钟 6 小时，末 30 分钟只收尾；有明确截止时间时取更早者。准备和依赖排查软预算 45 分钟，最多两次有明确原因的修复重试。无可行路径时登记阻塞，继续独立审计；不反复安装、下载、重提相同失败任务来耗完预算。

单个完整场景测实际吞吐与峰值显存后估计全量耗时。来不及跑完全量时保存已完成样本与状态，标为部分完成。mini / 子集只作试跑或范围受限证据，不判断全量论文数字。

检查实际 GPU、每卡显存、配额、运行上限，不预设一定是 T4。两张 16GB GPU 不等于单卡 32GB，分布式执行须确认代码支持；资源忙时先推进 CPU 审计。

OOM / 超时后不自动降低分辨率、改变精度、删任务头、缩短时序、改 split、换权重。只采用经检查确认不改变目标推理语义的执行调整，并记录两臂是否一致；会改变设置时提交新方案，保留已有结果。

### 4. 新训练的前置条件

任何新训练，包括 Ego-MLP、补训 VAD / UniAD，必须先提交并获得用户明确确认：

### 5. 共享与配对

各作业只写自己的目录；共享产物只读引用，记录生产者、路径、run ID、hash，不覆盖其他 Agent 的代码与状态。共享资源用原子锁或等价互斥机制，记持有者和实际远端运行，不仅因锁文件较旧便删锁重提。

配对使用相同样本，报告失败与剔除原因，不静默取有利交集。缓存身份包含扰动条件、时序状态策略；完全屏蔽视觉的实验不能复用 clean 视觉产生的 BEV / 历史特征。

## Agent A 后缀：BEVDet 两卡

你负责：

### A1. 优先完成 Scale-NMS 配对

Table 5 论文声称，尚未独立验证：

- mAP：NMS 0.295 → Scale-NMS 0.312，+1.7 个百分点。
- pedestrian AP：0.297 → 0.345，+4.8 个百分点。
- traffic cone AP：0.425 → 0.500，+7.5 个百分点。

先查 Table 5 配置与可得 checkpoint 的关系。「与 Table 4 D 行同配置」是整理者推断，不因 mAP 相同就当成已对齐。无法确定原消融权重时仍可做当前权重的开关实验，但不称精确复得 Table 5。

同 checkpoint、同 nuScenes val token 集做 NMS / Scale-NMS 配对。若有官方对应 Circular-NMS，余量允许补第三行；缺少实现就留缺口，不自创算法代替。

缓存可重放的 NMS 前候选框，避免重复 backbone。缓存不得已执行 Scale-NMS 或按某策略提前截断；列出候选过滤、NMS 阈值、top-k、策略参数。除策略及有出处的策略参数外，其余一致。

核查类别缩放表、作用位置、之后是否恢复原框尺寸、barrier 实现，以及「验证集搜索缩放因子」是否有证据。固定官方参数，不在复核 val 上重新调参追论文数字；另做调参必须作为探索独立报告。

报告全类 AP、mAP、NDS、配对差值、样本数。TP / 冗余框 IoU 分布属机制补充，不由 AP 改善反推「经典 NMS 必然失效」。

### A2. 扩展精度、GFLOPs 与 FPS

Table 2 论文参照，尚未独立验证：

| 方法 | mAP | NDS | GFLOPs | FPS |
| --- | --- | --- | --- | --- |
| BEVDet-Tiny | 0.312 | 0.392 | 215.3 | 15.6 |
| FCOS3D | 0.295 | 0.372 | 2008.2 | 1.7 |

两份匹配官方权重，在同 nuScenes val、无 TTA / ensemble 下复算精度。A1 仅在配置、权重、后处理一致时可复用。FCOS3D 不可得仍交 Tiny 与计算量部分，不把论文 FCOS3D 数字当自己的复测。

GFLOPs 说明工具版本、FLOPs / MACs 换算、每图还是六相机一帧、padding 后尺寸、算入 / 排除模块、自定义或动态算子漏算。两方法单位统一，报告实测比；215.3 / 2008.2 约 10.72%，论文称约 11%。漏算总数只能记为不完整计数，不能解释成效率收益。

FPS 只作测量条件受限的侧证据。统一 GPU、精度、输入协议，固定 warmup、计时次数、GPU 同步及计时边界，说明是否计预处理、传输、后处理。记录单图 / 六图 batch / 六相机完整样本关系；核对论文「单目速度除以 6」，不对已有六相机 FPS 再除一次。

其他 GPU 上测得某个 FPS 不等于复现 9.2×；吞吐与 GFLOPs 分开判断，batch 调度本身不改变算法计算量比。

最低有效交付：NMS 两臂的来源、匹配配置、同 token 结果。第二卡分别标 Tiny 精度、FCOS3D 精度、GFLOPs、FPS 完成情况。先保证首要配对，再用余量扩展。
