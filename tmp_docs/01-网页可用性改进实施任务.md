## 3. P0：修复新建与保存校验

### 目标行为

1. 创建时构造“已有集合 + 新候选”；编辑时构造“以候选替换目标卡后的集合”。候选提供正确的 `file`、`rel`、`data`，使文件名与 id 校验也真实生效。
2. 检查重复 id、目标文件冲突、必填字段、证据、falsifiers、日期、note 路径与 related id。已有库非法时应返回可理解的错误，不绕过校验。
3. 必填文本不能仅为空白；证据条目、falsifiers 的空值不能靠空数组占位或空字符串混过检查。保持共享校验逻辑与 schema 的要求一致。
4. 失败时不写 claim、不更新索引；成功后才执行原子写入并重建索引。写盘/索引失败应如实反馈，不能显示“已完整保存”。
5. 新卡固定 `asserted`；现有 `id / type / status / signoff` 不能通过编辑接口改变。只读实例和非 `asserted` 卡的写入保护继续有效。
6. 网页提供可发现的“新建 claim”入口。成功创建后列表、计数和详情应及时刷新，不能只跳详情而保留旧列表数据。

### 必须验证

- 合法新卡可以创建并重新读取，文件名和 id 一致，索引含该卡。
- 缺标题、scope、evidence、falsifiers，空白必填内容、无效来源路径、无效日期、未知 related id、重复 id 均拒绝；失败前后夹具中的卡片与索引不变。
- 编辑只替换目标卡；未修改字段保持保真，`signoff` 不被触碰。
- `--readonly` 与非 `asserted` 卡的写操作被服务端拒绝。
- 测试覆盖真实创建/保存入口，不能只验证一个新造的辅助函数。可提取可测的服务模块或让服务使用临时夹具根目录；生产默认仍指向真实仓库。

## 4. P1：搜索、笔记阅读与关联 claim

### 4.1 导航与检索

建议导航为“资料 / 今日复核 / 全部 Claim / 图谱”；资料页作为默认入口。保留已有 claim、队列和图谱链接的可访问性。

- 资料页按现有 `library/` 分类浏览笔记，不另造一份需要人工维护的目录。
- 全库搜索覆盖：笔记标题、相对路径、正文；claim 的 id、title、tags、scope、证据文本和正文。支持中文、英文及多个关键词；第一版使用确定性的文本匹配即可，说明多词匹配规则。
- 搜索结果分清“来源笔记 L1”和“Claim”。展示标题、路径/来源、命中片段；claim 始终显示 `status` 和 `stance`，`asserted` 标为“尚未独立验证”。
- 点击笔记结果进入阅读页并尽可能定位命中章节；点击 claim 进入详情。返回搜索时保留关键词、筛选和位置。
- 默认搜索正式笔记，排除 `library/assets/` 内的论文转换全文，避免原始材料淹没整理后的笔记；`library/README.md` 可作为目录入口，不伪装成论文。
- 第一版无需 PDF 全文检索、OCR、联网搜索或生成式问答；PDF 可提供明确的原文件入口。
- 文件手工修改后，刷新或重新查询能读取新内容；如用缓存/派生索引，必须有明确刷新或失效策略。

### 4.2 独立阅读页

- 支持标题层级、段落、列表、引用、代码块、表格、行内/块级数学公式、图片与章节锚点。
- 图片保持比例，可放大查看；长表格和公式在窄屏下可横向查看，不能撑破整个页面。
- 相对链接按原笔记所在目录解析。区分：同文档锚点、其他笔记、claim、图片/PDF、外部链接。含空格、中文、编码字符的路径可用。
- 提供来源文件路径/原文件入口，方便使用原编辑器核对。没有原论文链接时不猜测补齐。
- 阅读页默认只读；本任务不增加 `library/` 在线编辑。
- 安全地渲染 Markdown：不执行嵌入脚本，链接与资源加载过滤危险协议，资源接口限制在允许的真实目录内；不能因渲染功能暴露仓库外文件。
- 保持本地可用与无构建的启动体验。若为 Markdown/数学渲染引入必要的静态库，优先固定版本并本地托管，记录来源与许可证；不依赖运行时 CDN，不为此引入整套前端框架。此为本轮技术路线建议，不应把一期的简化渲染当作完成标准。

### 4.3 笔记与 claim 双向访问

- 笔记旁列出关联 claim：使用 `note`，并补充 `evidence.source` 对该笔记的引用；规范化路径、去锚点并去重。
- 区分“主要来源”和“证据引用”会更清楚；没有明确引用关系时，不按标题相似或共同 tag 自动制造关联。
- 每项显示标题、状态、立场和关键 scope；点击进入详情。
- claim 详情中，来源笔记与每条可解析的证据源可点击，能返回相应文件/章节；不能把所有 `.md` 链接一律改成 claim 链接。
- 关联列表表示引用关系，不能展示为“已证实的结论”。没有关联 claim 的笔记也应能独立阅读。

### 阅读链路验收

用仓库内真实存在的内容选取以下案例，报告具体笔记与查询词：

1. 关键词只出现在笔记正文中：能查到、看到命中片段并打开对应笔记。
2. 关键词只出现在 claim 正文或证据中：能查到，且状态与立场可见。
3. 带表格、公式、本地图片的笔记：与原文件对照显示正确；验证空格/中文路径和章节跳转。
4. 同一笔记通过 `note` 和 `evidence.source` 被同一张卡引用：只列一次；只被 evidence 引用的卡也能找到。
5. 搜索 → 笔记 → claim → 返回：上下文可找回；手机端也能完成主要阅读流程。
6. 恶意路径、目录穿越、危险链接与脚本内容被正确处理；正常资源仍可读取。

## 5. P2：让今日复核可完成

### 5.1 调度与知识状态分开

本轮优先复用 `review_due`，不新增知识状态，不批量改写现有卡的日期。建议确定以下视图语义：

| 视图 | 纳入规则 | 用户能做什么 |
|---|---|---|
| 今日待办 | `asserted` 且 `review_due <= 服务端今天` | 阅读、记录、安排下次复核、顺延。 |
| 以后处理 | `asserted` 且日期在未来 | 查看安排；主动调整为今天即可进入今日待办。 |
| 未安排 | `asserted` 且无 `review_due` | 用户选择日期；不默认全部挤进今日。 |
| 全部未验证 | 全部 `asserted` | 保留完整检索入口，与今日工作量区分。 |
| 待用户处理 | 全部 `stale`，以及到期的 `verified` | 展示原因、证据和文件入口；保持只读，由用户手工处理。 |

`refuted` 保留在全部 Claim 中，不自动进入今日待办。受保护卡的人工处理提醒与可完成的 `asserted` 待办分别计数。

已有未来日期意味着首屏可能没有今日待办，这是合理结果；页面可引导查看“未安排 / 全部未验证”并主动选卡，不为制造任务而回填历史日期。

### 5.2 操作语义

- 将“标记已复核”改为含义明确的文案，例如“本次处理完成，下次 90 天后”；明确只安排下一次日期，不能使人误以为已验证。
- 执行后将 `review_due` 设为服务端今天 + 90 天；顺延 30 天设为今天 + 30 天。该卡立即退出今日待办，刷新后仍如此，并能在以后处理/全部未验证中找到。
- 如果记录“本次查了什么、还有什么没查”，内容由操作者填写，记录到 asserted 卡的核查记录中；不可由点击按钮自动生成“已核对原文”等事实。
- “今天处理”可通过显式设置 `review_due = 今天` 实现；单纯浏览卡片不改变日期。
- `status`、`stance`、`signoff` 不因调度操作改变。非 asserted 卡不显示可执行写按钮；服务端仍拒绝写入。
- 所有计数使用同一语义；分别标注全库数量与筛选后数量。“筛选无结果”不能显示成“全部任务已完成”。
- 日期按服务端提供的 `today` 计算，不混用手机与服务端的跨日判断。处理跨月、跨年以及当天边界。

### 5.3 CLI 与旧行为

`ka.mjs review` 现有语义是完整待关注清单，本轮可保留并明确文案，与“今日待办”区分。若添加今日筛选选项，则共享规则并补测试；不要悄悄改变旧命令含义。同步更新 API 计数、前端、README 与相关注释，避免各层仍把旧全量队列标作今日任务。

### 队列验收

用隔离夹具覆盖：asserted 的过去/今天/未来/无日期，verified 的到期/未到期，stale、refuted。

- 今日待办精确符合上表；完成、顺延后从今日消失且重载结果一致。
- 所有卡仍能通过相应资料/列表入口找回；没有被删除或升级状态。
- 非 asserted 卡和所有 signoff 字节不变，普通浏览不产生写入。
- 检查筛选空结果与真正无待办两种空态；统计数字不相互矛盾。
